# 색 조합 비교

[HTML 비교 화면](./color-combinations.html)을 내려받아 브라우저에서 열면 같은 산책 기록 화면을 여덟 가지 색으로 볼 수 있다. 레이아웃과 글자는 같고, 바탕·본문·표면·강조색만 다르다.

느낌은 이 화면에서의 해석이다. 같은 색도 면적, 서체, 사진, 문화적 맥락에 따라 다르게 보인다. 아래 용도는 추천 예시이지 정해진 규칙이 아니다.

구성까지 다른 화면은 [분위기별 HTML 예시](./mood-examples.html)와 [18가지 추가 배색 문서](./mood-examples.md)에 있다. 독서·음악·여행·전시·작업 도구·카페 화면마다 세 조합을 비교한다. 이 문서의 여덟 조합과 합쳐 총 26가지다.

## 앱에 옮길 때

- 먼저 `background`, `text`, `surface`, `accent`, `on-accent`처럼 역할에 연결한다. 버튼·링크·선택·오류를 같은 강조색으로 일괄 교체하지 않는다.
- 이 예시의 일반 텍스트 조합은 WCAG 대비 계산으로 **4.5:1 이상**인지 확인했다. 실제 앱에서는 호버·비활성·오류·포커스와 이미지 위 글자까지 다시 측정해야 한다.
- 다크 조합 두 개는 별도의 팔레트다. 라이트 팔레트의 RGB를 반전한 것이 아니며, 자동 테마 전환 예제도 아니다.
- 숫자 뒤 강조 면적은 여덟 화면에서 동일하다. 배경을 강조색으로 바꾸거나 사진을 넣으면 이 비교와 인상이 달라진다.
- HTML의 기록 값은 고정된 시연 데이터다. 앱 기능이나 저장 동작은 없고, 각 화면 아래의 색 코드만 펼칠 수 있다. 외부 폰트·이미지·스크립트를 사용하지 않았다.

이 자료는 문서용 시각 예시다. MCP 패턴 카탈로그에 등록된 예제가 아니므로 기존 138개 범용 패턴 및 대표 웹 예제 10개의 집계에는 포함하지 않는다.

MCP 0.3.0부터 별도 시각 예시로 등록했다. `search_design_visuals`로 `배색`을 검색하거나 `get_design_visual`의 `id=color-combinations`로 조회한다. `includeSource=true`는 HTML을 반환한다. 기존 패턴 집계는 그대로다.

원칙은 [색상·테마 지침](../../content/library/color-theming.json), 기존 프로젝트의 팔레트 적용은 [색상, 배경면과 대비](../../content/guides/colors-and-surfaces.md)를 참고한다. 더 큰 색면을 쓴 예시는 [야간 러닝 이벤트](../posters/high-energy.html)에 있다.

## 사용자 제공 레퍼런스 색감 분석

> 예시별 분석 JSON에서 자동 생성한다. 추가·수정은 [분석 등록 안내](<../../docs/recording-analyses.md>)를 따른다. MCP: `design://analysis-logs/color`.

위 8개 비교 시안과 별도로, 사용자가 제공한 예시의 색감 관찰을 모은다. `estimated`는 프레임에서 추출한 표본 등 추정값으로, 원본의 확정 색상은 아니다.

### 도트로 만든 두 얼굴 — 밝은 하프톤 모션의 색감·레이아웃·폰트

수정 2026-11-18 · [상세 분석·근거](<../../docs/analyses/halftone-talking-heads-study.md#색감-분석>)

따뜻한 오프화이트가 화면의 넓은 바탕을 맡고, 얼굴은 웜 그레이와 탁한 로즈 계열의 작은 표식으로 나타난다. 강한 발광이나 검정 배경 없이 색의 절제와 명암 차이로 디지털 인물의 존재감을 만든다.

| 역할 | 값 | 확인 수준 |
| --- | --- | --- |
| 오프화이트 바탕의 프레임 표본 | #f2efec | estimated |
| 왼쪽 얼굴의 어두운 표식 대표 표본 | #a69c99 | estimated |
| 오른쪽 얼굴의 따뜻한 표식 대표 표본 | #c39591 | estimated |

**색온도와 채도** · `color.temperature-saturation`

- **배색 관계** (confirmed): 관찰 프레임에서 왼쪽 얼굴은 상대적으로 중립적인 회색, 오른쪽 얼굴은 분홍·붉은 기가 더 드러난다. 피부를 면으로 채우지 않고 밝은 바탕 사이로 표식을 남겨 전체 인상이 가볍다. · 근거: overview-frames, detail-frame
- **분위기에 대한 해석** (estimated): 따뜻한 바탕과 옅은 피부색을 연상시키는 표식이 데이터적인 표현을 차갑지 않게 만든다고 해석할 수 있다. 이는 시각 효과에 대한 분석이며 사용자가 이 예시를 좋아하는 정확한 이유를 확인한 진술은 아니다. · 근거: detail-frame

**명도와 대비** · `color.contrast`

- **색보다 명암으로 드러나는 형태** (estimated): 눈·코·입 주변에서 표식의 어두움과 크기·간격 차이가 얼굴을 읽게 한다. 외곽과 밝은 부분은 바탕에 가까워져 사라지는 듯 보인다. 이를 실제 깊이값·법선·투명도 중 무엇으로 계산했는지는 확인할 수 없다. · 근거: detail-frame

**팔레트와 역할** · `color.palette-roles`

- **숫자의 확인 범위** (confirmed): HEX는 디코딩된 6초 프레임에서 정해진 영역·조건으로 구한 RGB 표본의 중앙값이다. 원본 CSS·셰이더의 색상 선언이나 디스플레이에서 보이는 색을 확인한 값은 아니므로 재사용 팔레트로서는 추정으로 기록한다. 색의 면적 비율과 텍스트 대비율은 측정하지 않았다. · 근거: frame-color-samples
- **콘텐츠와 녹화 UI의 구분** (confirmed): 황갈색 광고 버튼, 흰 소셜 아이콘, 상태 표시줄의 빨강, 최하단 검정 영역도 보이지만 얼굴 그래픽 자체의 핵심 배색과 구분한다. 앱 UI의 색을 원본 작품의 팔레트로 일괄 흡수하지 않는다. · 근거: detail-frame, overview-frames

**재사용**

- 따뜻한 밝은 바탕과 중립색·로즈의 역할 관계만 추출하고, 얼굴이나 도트 효과를 쓰지 않는 화면에도 독립적으로 적용할 수 있다.
- 그래픽의 낮은 대비를 본문·상태·버튼에 그대로 적용하지 않는다. 기능 정보는 별도로 대비와 상태 식별을 검수한다.
- 추출 HEX를 원본의 확정 색으로 복제하지 말고 최종 배경·합성 방식·출력 기기에서 다시 조정한다.

**색온도와 채도** · `color.temperature-saturation`

- **따뜻하고 차가운 어둠** (confirmed): 따뜻한 적색과 차가운 청록이 서로 다른 색 방향을 만들고, 밝은 영역에는 흰색 대신 복숭아빛이 도는 크림을 쓴다. · 근거: pin-preview

**재사용**

- 비슷하게 어두운 두 색에 동등한 무게를 줄 때 색온도를 달리하고, 판독에 필요한 명도 차이는 밝은 중립색에서 확보한다.
