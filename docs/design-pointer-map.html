02 / 연결

MCP 포인터가 가리키는 곳

클라이언트는 등록된 design 설정을 통해 MCP 서버에 연결합니다. 서버는 설정에 연결된 로컬 빌드나 설치 패키지의 자료를 읽습니다. 조회할 때마다 GitHub에 접속하는 게 아닙니다.

어디를 보나 · Copilot Global 설정 예
mcpServers.design
node …/DESIGN/dist/index.js

03 / MCP 리소스

공통 규칙부터 읽기

사례를 보기 전에 모든 프로젝트에 공통으로 적용하는 디자인 원칙과 검수 기준을 읽습니다.

어디를 보나 · 리소스 URI
design://design-cautions

04 / MCP 도구

사용자 선호 확인

선호 프로필에서 사용자가 직접 요청한 기준과 여러 레퍼런스에서 반복 관찰된 특징을 구분해 봅니다.

어디를 보나 · 도구
get_design_preferences

05 / MCP 도구

분위기와 활용처로 검색

사용자가 고른 레퍼런스에서 ‘고요·고립감’과 ‘전시 랜딩’을 함께 검색합니다. 사례 ID를 이미 알면 검색을 건너뛰고 상세를 조회할 수 있습니다.

어디를 보나 · 도구와 예시 인자
search_design_analyses
{
  "scope": "preferred",
  "character": {"dimension": "mood", "query": "고요 고립감"},
  "useCase": "전시 랜딩"
}

06 / MCP 도구

〈Moon〉의 관찰 근거 확인

〈Moon〉 기록에서 큰 구조와 작은 전신 인물의 크기 차를 확인합니다. 가져올 것은 대비의 원리이지, 동심원이나 우주인 자체가 아닙니다.

어디를 보나 · 도구와 사례 ID
get_design_analysis
{"id": "pinterest-moon-concentric-poster"}

우회 / MCP 밖

원문만 별도로 열람

조회 결과만으로 충분하지 않을 때 AI가 별도로 보고서나 소스를 엽니다. MCP가 GitHub 전체를 내려받거나 실행 중인 사본을 자동 갱신하는 단계가 아닙니다.

어디를 보나 · 원문
공개 DESIGN 저장소 또는 접근 가능한 로컬 사본

07 / 복귀

근거를 현재 프로젝트로

조회만 요청하면 근거와 적용 방안을 설명합니다. 구현도 요청하면 현재 프로젝트의 AI가 대상 파일을 수정하고 실제 화면을 검수합니다.

어디를 보나
현재 프로젝트의 채팅 · 구현 요청 시에만 대상 프로젝트 파일

지도 시안입니다. 정거장을 눌러도 실제 MCP를 호출하거나 파일을 수정하지 않습니다.
